## 방향

- 개인 컴퓨터에서 실행하는 **exe** 앱이다.
- 나와 **에이전트**(에이전트 하나 = 터미널 세션 하나)가 함께 일하는 방식이다. 사람끼리의 팀 협업은 다루지 않는다.
- 로그인은 없다. exe를 실행하면 바로 대시보드가 열린다.
- React 화면은 데이터를 FastAPI를 거쳐서 가져온다.

## 결정할 것

| # | 질문 | 결정 |
|---|---|---|
| 1 | 누가 쓰나? (나 혼자 / 여러 사람이 가입) | 나 혼자. 에이전트와 협업 |
| 2 | 메일은 어디서 오나? (Gmail 등 연동 / 서비스 안 메시지) | Gmail, 네이버, 회사 메일 등 외부 메일 연동. AI가 요약 · 답장 초안 생성, 전송은 사용자가 버튼을 눌러야만 |
| 3 | 무엇을 결재하나? (에이전트가 실행하려는 명령 승인 / 에이전트의 다른 요청 / 둘 다) | 미정 |
| 4 | 일정은 어디에 저장하나? (서비스 DB / Google Calendar 등 연동) | 앱 DB. 2섹션에서 추가한 할 일이 달력과 다가오는 일정에 보인다 |
| 5 | Agent 탭의 AI 팀원은? (챗봇 하나 / 역할별 에이전트 여러 개) | 역할별 에이전트 여러 개. 에이전트 하나 = 터미널 세션 하나 |
| 6 | 챗봇이 처음부터 명령을 실행하나? (대화만 먼저 / 실행까지) | 미정 |
| 7 | 무엇부터 만드나? | 미정 |

| 데이터 | 저장 |
|---|---|
| 할 일, 에이전트 대화 기록, 메일 요약, 결재 요청 | SQLite |
| 앱 설정 (창 크기, 테마 등) | JSON 파일 |
| 메일 비밀번호, 토큰 | Windows 자격 증명 관리자 |

## 에이전트 연결

에이전트는 **공식 CLI 에이전트**(Claude Code, Codex 등)를 터미널 세션 안에서 실행한다.

- 에이전트 하나 = 터미널 세션 하나 = CLI 프로세스 하나.
- 로그인은 각 CLI가 처음 실행될 때 자기 방식(브라우저 로그인)으로 한다. 앱은 AI 로그인 토큰을 다루지 않는다.
- 역할별 에이전트마다 다른 CLI를 쓸 수 있다.
- 4섹션은 **터미널 화면 그대로** 보여 준다.

| 부분 | 사용 기술 |
|---|---|
| 4섹션 터미널 화면 (React) | xterm.js |
| 화면과 백엔드 연결 | WebSocket. 키 입력은 백엔드로, 터미널 출력은 화면으로 실시간 전달 |
| 터미널 세션 (FastAPI) | pywinpty. 에이전트마다 CLI 프로세스를 하나씩 띄운다 |

## 화면 구조

- 위젯 형식 + 사이드 패널

왼쪽부터 섹션 4개로 나눈다. 1~3은 위젯, 4는 사이드 패널.

| 섹션 | 형식 | 위젯 |
|---|---|---|
| 1 | 위젯 | 다가오는 일정, Agent |
| 2 | 위젯 | 할 일, 일정(달력) |
| 3 | 위젯 | 메일 검토, 결재 대기 |
| 4 | 사이드 패널 | 챗봇 |

```
┌──────────┬──────────┬──────────┬──────────────┐
│ 1        │ 2        │ 3        │ 4            │
│          │          │          │              │
│ 다가오는 │ 할 일    │ 메일     │ 챗봇         │
│ 일정     │          │ 검토     │              │
│          │          │          │              │
│ Agent    │ 일정     │ 결재     │              │
│          │ (달력)   │ 대기     │              │
└──────────┴──────────┴──────────┴──────────────┘
```
