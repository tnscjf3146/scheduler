# 기능 명세 (MVP)

Jira 비슷한 이슈 트래커의 MVP 기능 목록. 범위는 [Jira 구조 분석](../../analysis/jira-structure.md#mvp-범위), 데이터는 [ERD](../erd.md), 세부 규칙은 [정책](../policy/policy.md)을 따른다.

- 대상: 웹(React)과 앱(Compose Multiplatform, Android 먼저). 기능은 같다.
- 기능 ID는 `{도메인}-{번호}`. 명세·정책·이슈에서 이 ID로 부른다.

## 서비스 개요

팀이 프로젝트 단위로 할 일을 **이슈**로 만들어 **백로그**에 쌓고, **스프린트**에 담아 **보드**에서 상태를 옮기며 진행을 관리한다.

```
회원가입 → 프로젝트 생성 → 멤버 추가 → 이슈 생성(백로그) → 스프린트 계획 → 스프린트 시작
→ 보드에서 드래그로 진행 → 스프린트 완료 (남은 이슈는 다음 스프린트·백로그로)
```

## 사용자 (USER)

| ID | 기능 | 설명 |
|---|---|---|
| USER-1 | 회원가입 | 이메일, 비밀번호, 이름으로 가입 |
| USER-2 | 로그인 · 로그아웃 | 이메일, 비밀번호 |
| USER-3 | 내 정보 수정 | 이름, 비밀번호 변경 |
| USER-4 | 탈퇴 | 계정과 멤버십을 즉시 삭제. 작성한 이슈·댓글은 남는다 ([정책](../policy/policy.md#탈퇴)) |

## 프로젝트 (PRJ)

| ID | 기능 | 설명 |
|---|---|---|
| PRJ-1 | 프로젝트 생성 | 이름, 프로젝트 키, 설명, 스프린트 사용 여부(기본 켬). 만든 사람이 리드·관리자가 된다. 기본 상태 3개와 기본 이슈 유형 5개가 함께 생긴다 |
| PRJ-2 | 프로젝트 목록 | 내가 멤버인 프로젝트 |
| PRJ-3 | 프로젝트 설정 수정 | 이름, 설명, 리드, 스프린트 사용 여부 변경. 키는 바꿀 수 없다 |
| PRJ-4 | 프로젝트 삭제 | 프로젝트 키를 입력해 확인. 딸린 데이터가 모두 지워진다 |
| PRJ-5 | 멤버 추가 | 가입한 사용자를 이메일로 찾아 추가 |
| PRJ-6 | 멤버 역할 변경 · 내보내기 | 관리자 / 멤버 |
| PRJ-7 | 프로젝트 나가기 | 리드와 마지막 관리자는 나갈 수 없다 |

## 워크플로 (WF)

| ID | 기능 | 설명 |
|---|---|---|
| WF-1 | 상태 목록 | 보드 열 순서대로 |
| WF-2 | 상태 추가 | 이름과 분류(할 일 / 진행 중 / 완료)를 정한다 |
| WF-3 | 상태 수정 | 이름 변경, 순서 변경. 분류는 바꿀 수 없다 |
| WF-4 | 상태 삭제 | 그 상태의 이슈를 옮길 상태를 고른 뒤 삭제 |
| WF-5 | 이슈 유형 목록 · 추가 · 수정 · 삭제 | 상태와 같은 방식. 분류 대신 계층(에픽 / 일반 / 하위 작업)을 정한다 |

## 이슈 (ISSUE)

| ID | 기능 | 설명 |
|---|---|---|
| ISSUE-1 | 이슈 생성 | 유형, 제목 필수. 설명, 담당자, 우선순위, 레이블, 기한, 부모, 스프린트 선택. 키(`SCH-12`) 자동 발급 |
| ISSUE-2 | 이슈 상세 | 모든 필드, 하위 이슈 목록, 댓글 |
| ISSUE-3 | 이슈 수정 | 필드마다 바로 수정 (상세 화면에서 클릭 → 편집) |
| ISSUE-4 | 상태 변경 | 상세 화면의 상태 선택, 또는 보드에서 드래그 |
| ISSUE-5 | 이슈 삭제 | 확인 창. 하위 작업과 댓글이 함께 지워진다 |
| ISSUE-6 | 레이블 | 이슈에 여러 개 붙이기. 없는 이름이면 새로 만든다 |
| ISSUE-7 | 에픽 진행률 | 에픽의 하위 이슈 중 완료 분류 상태인 비율 |

### 이슈 필드

| 필드 | 필수 | 기본값 |
|---|---|---|
| 유형 | O | - |
| 제목 | O | - |
| 상태 | 자동 | 할 일 분류의 첫 번째 상태 |
| 우선순위 | 자동 | 보통 (`MEDIUM`) |
| 보고자 | 자동 | 만든 사람 |
| 스프린트 | | 백로그에서 만들면 없음(백로그), 보드에서 만들면 진행 중 스프린트 |
| 설명, 담당자, 부모, 레이블, 기한 | | 비어 있음 |

## 백로그 (BACKLOG)

스프린트 사용이 켜진 프로젝트에만 있다.

| ID | 기능 | 설명 |
|---|---|---|
| BACKLOG-1 | 백로그 화면 | 위에서부터 진행 중 스프린트, 계획된 스프린트들, 백로그(스프린트 없는 이슈) 순으로 이슈 목록을 보여준다 |
| BACKLOG-2 | 순서 정하기 | 드래그로 우선순위 순서를 바꾼다 |
| BACKLOG-3 | 스프린트에 넣고 빼기 | 이슈를 스프린트 영역으로 끌어다 놓거나, 이슈 메뉴에서 스프린트를 고른다. 여러 개를 골라 한 번에 옮길 수 있다 |
| BACKLOG-4 | 빠른 생성 | 백로그·스프린트 영역 맨 아래에서 제목만 입력해 이슈를 만든다 |

## 스프린트 (SPRINT)

스프린트 사용이 켜진 프로젝트에만 있다.

| ID | 기능 | 설명 |
|---|---|---|
| SPRINT-1 | 스프린트 생성 | 이름은 자동(`SCH 스프린트 1`), 바꿀 수 있다 |
| SPRINT-2 | 스프린트 시작 | 관리자가 직접 시작한다 (날짜로 자동 시작하지 않음). 기간(기본 2주)과 목표를 정한다. 진행 중 스프린트는 하나뿐이다 |
| SPRINT-3 | 스프린트 수정 | 이름, 목표, 기간 |
| SPRINT-4 | 스프린트 완료 | 관리자가 직접 완료한다 (종료일이 지나도 자동 완료하지 않음). 완료된 이슈 수·남은 이슈 수를 보여주고, 남은 이슈를 보낼 곳(백로그 또는 계획된 스프린트)을 고른다 |
| SPRINT-5 | 스프린트 삭제 | 계획된 스프린트만. 이슈는 백로그로 돌아간다 |
| SPRINT-6 | 지난 스프린트 | 완료된 스프린트 목록과 그때 완료된 이슈 |

## 보드 (BOARD)

| ID | 기능 | 설명 |
|---|---|---|
| BOARD-1 | 보드 | 이슈를 상태별 열에 카드로. 카드: 키, 제목, 유형, 우선순위, 담당자, 기한. 스프린트 사용이 켜져 있으면 **진행 중 스프린트의 이슈**만(없으면 "백로그에서 스프린트를 시작하세요" 안내), 꺼져 있으면 **모든 이슈**(칸반) |
| BOARD-2 | 드래그 앤 드롭 | 다른 열로 옮기면 상태 변경, 같은 열 안에서 옮기면 순서 변경 |
| BOARD-3 | 보드 필터 | 담당자, 유형, 우선순위, 레이블, "내 이슈만". 여러 조건을 함께 건다 |
| BOARD-4 | 에픽 숨기기 | 에픽은 보드에 카드로 나오지 않는다. 대신 카드에 소속 에픽 이름을 표시 |

- 앱(모바일)은 화면이 좁아 열을 가로 스와이프로 넘긴다. 카드를 길게 눌러 드래그한다.

## 대시보드 (DASH)

프로젝트에 들어가면 처음 보이는 화면. 위젯 구성은 고정이고 모든 멤버가 같은 화면을 본다.

| ID | 기능 | 설명 |
|---|---|---|
| DASH-1 | 내 이슈 | 나에게 배정된 미완료 이슈. 기한 가까운 순 |
| DASH-2 | 상태별 이슈 수 | 분류(할 일 / 진행 중 / 완료)별, 상태별 이슈 수 |
| DASH-3 | 담당자별 이슈 수 | 담당자별 미완료 이슈 수. 미배정 포함 |
| DASH-4 | 우선순위별 이슈 수 | 미완료 이슈의 우선순위 분포 |
| DASH-5 | 기한 지난 이슈 | 기한이 지난 미완료 이슈 목록 |
| DASH-6 | 생성 · 해결 추이 | 최근 30일 날짜별 생성 이슈 수와 해결 이슈 수 (선 그래프) |
| DASH-7 | 스프린트 진행률 | 진행 중 스프린트의 완료 비율, 남은 일수. 스프린트 사용이 켜진 프로젝트만 |
| DASH-8 | 에픽 진행률 | 미완료 에픽별 하위 이슈 완료 비율 |

- 각 위젯의 숫자·항목을 누르면 그 조건으로 걸러진 이슈 목록(SEARCH-1)으로 이동한다.

## 검색 (SEARCH)

| ID | 기능 | 설명 |
|---|---|---|
| SEARCH-1 | 이슈 목록 | 프로젝트의 모든 이슈를 표로. 정렬: 생성일, 수정일, 우선순위, 기한 |
| SEARCH-2 | 검색 · 필터 | 키·제목 검색 + 상태, 유형, 담당자, 우선순위, 레이블 필터 |
| SEARCH-3 | 키로 바로 가기 | `SCH-12`를 입력하면 그 이슈 상세로 이동 |

## 댓글 (CMT)

| ID | 기능 | 설명 |
|---|---|---|
| CMT-1 | 댓글 작성 | 마크다운. `@`를 입력하면 프로젝트 멤버 목록이 떠 멘션할 수 있다 |
| CMT-2 | 댓글 수정 · 삭제 | 수정하면 "수정됨" 표시 |

## 알림 (NOTI)

| ID | 기능 | 설명 |
|---|---|---|
| NOTI-1 | 알림 목록 | 벨 아이콘. 최신순, 안 읽은 알림 강조 |
| NOTI-2 | 안 읽은 알림 수 | 벨 아이콘에 숫자 표시 |
| NOTI-3 | 읽음 처리 | 알림을 누르면 그 이슈로 이동하며 읽음. "모두 읽음" 버튼 |

- 알림이 생기는 경우와 받는 사람은 [정책](../policy/policy.md#알림)을 따른다.

## MVP에서 제외

| 기능 | 시기 |
|---|---|
| 첨부파일, 이슈 링크, 변경 이력, 관찰자, 상태 전환 규칙, 버전 · 컴포넌트, 스프린트 보고서(번다운 · 속도), 스토리 포인트 | 다음 단계 |
| 이메일 · 푸시 알림, 소셜 로그인, 프로필 이미지 | 다음 단계 |
| 시간 흐름 차트 (번다운, 누적 흐름도) | 다음 단계 (변경 이력 필요) |
| JQL, 사용자가 꾸미는 대시보드, 타임라인, 자동화, 사용자 정의 필드, 외부 연동 | 미룸 |
