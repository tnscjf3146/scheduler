# 정책 (MVP)

[기능 명세](../spec/feature-spec.md)의 세부 규칙. 데이터 구조는 [ERD](../erd.md)를 따른다.

## 권한

프로젝트 안의 권한은 역할(`ADMIN`, `MEMBER`)로 정한다. 프로젝트 멤버가 아니면 그 프로젝트의 어떤 것도 볼 수 없다.

| 할 일 | 관리자 | 멤버 | 비고 |
|---|---|---|---|
| 이슈 보기 · 생성 · 수정 · 상태 변경 | O | O | |
| 이슈 삭제 | O | 보고자만 | |
| 댓글 작성 | O | O | |
| 댓글 수정 | 작성자만 | 작성자만 | 남의 글은 관리자도 고치지 않는다 |
| 댓글 삭제 | O | 작성자만 | |
| 스프린트 생성 · 수정 · 이슈 넣고 빼기 | O | O | |
| 스프린트 시작 · 완료 · 삭제 | O | X | |
| 상태 · 이슈 유형 관리 | O | X | |
| 멤버 추가 · 역할 변경 · 내보내기 | O | X | |
| 프로젝트 설정 수정 · 삭제 | O | X | |

- 권한이 없는 기능은 화면에서 버튼을 숨기고, 서버에서도 막는다 (`FORBIDDEN`).

## 프로젝트

### 프로젝트 키
- 영문 대문자로 시작하는 **대문자·숫자 2~10자**. 예: `SCH`, `APP2`
- 서비스 전체에서 겹칠 수 없다. 삭제된 프로젝트의 키는 다시 쓸 수 있다.
- **바꿀 수 없다.** 이슈 키(`SCH-12`)가 커밋·메신저 등 밖에 공유되기 때문이다.

### 생성
- 만든 사람이 **리드**이자 **관리자**가 된다.
- 기본 상태 3개와 기본 이슈 유형 5개를 함께 만든다.
- 스프린트 사용 여부를 고른다 (기본 켬). [스프린트 사용 옵션](#스프린트-사용-옵션) 참고.

| 기본 상태 | 분류 |
|---|---|
| 할 일 | `TODO` |
| 진행 중 | `IN_PROGRESS` |
| 완료 | `DONE` |

| 기본 이슈 유형 | 계층 |
|---|---|
| 에픽 | `EPIC` |
| 스토리 | `STANDARD` |
| 작업 | `STANDARD` |
| 버그 | `STANDARD` |
| 하위 작업 | `SUBTASK` |

### 멤버
- 가입한 사용자만 이메일로 추가한다 (초대 메일은 MVP에 없다).
- **관리자는 항상 1명 이상**이다. 마지막 관리자는 역할을 바꾸거나 나갈 수 없다.
- **리드**는 관리자 중 1명이다. 리드는 나갈 수 없고, 먼저 다른 관리자에게 리드를 넘긴다.
- 멤버가 나가거나 내보내지면 그 사람이 담당자인 이슈는 **미배정**으로 바뀐다.

### 삭제
- 관리자만 할 수 있고, 확인 창에 **프로젝트 키를 직접 입력**해야 삭제된다.
- 상태, 이슈 유형, 스프린트, 이슈, 댓글, 레이블, 멤버, 관련 알림이 모두 지워진다. **복구할 수 없다.**

## 상태 (워크플로)

- 분류(`TODO`, `IN_PROGRESS`, `DONE`) 3개는 고정이다. 관리자는 그 아래에 상태를 만든다.
- **분류마다 상태가 1개 이상** 있어야 한다. 마지막 하나는 지울 수 없다.
- 상태 이름은 1~30자, 같은 프로젝트에서 겹칠 수 없다.
- 분류는 만든 뒤 바꿀 수 없다. 바꾸려면 새로 만들고 이슈를 옮긴 뒤 지운다.
- 순서(`position`)가 보드 열 순서다. 보드 열은 **할 일 → 진행 중 → 완료 분류 순서**로 묶여 놓이고, 순서는 **같은 분류 안에서만** 바꿀 수 있다 (설정 화면이 분류별 그룹이고, 보드 위에 분류 띠를 걸기 때문).
- **삭제**: 그 상태에 이슈가 있으면 옮길 상태를 고르게 하고, 이슈를 모두 옮긴 뒤 지운다.
- 상태 사이 이동은 자유다 (어느 상태에서 어느 상태로든). 전환 규칙은 MVP에 없다.

## 이슈 유형

- 계층(`EPIC`, `STANDARD`, `SUBTASK`) 3개는 고정이다. 관리자는 그 아래에 유형을 만든다.
- **계층마다 유형이 1개 이상** 있어야 한다. 마지막 하나는 지울 수 없다.
- 유형 이름은 1~30자, 같은 프로젝트에서 겹칠 수 없다.
- 계층은 만든 뒤 바꿀 수 없다. 바꾸면 이미 있는 이슈의 부모 관계가 깨진다.
- **삭제**: 그 유형의 이슈가 있으면 **같은 계층의** 다른 유형을 고르게 하고, 이슈를 옮긴 뒤 지운다.

## 이슈

### 키 발급
- 키는 `프로젝트 키-번호`. 번호는 프로젝트마다 1부터 1씩 늘어난다.
- 번호는 **다시 쓰지 않는다.** `SCH-12`를 지워도 다음 이슈는 `SCH-13`이다.

### 계층 (부모)

| 이슈 유형의 계층 | 부모 |
|---|---|
| `EPIC` | 없음 |
| `STANDARD` | 없거나, 같은 프로젝트의 에픽 |
| `SUBTASK` | **필수**. 같은 프로젝트의 `STANDARD` 이슈 |

- 부모를 바꿀 때도 위 규칙을 검사한다.
- 하위 작업이 있는 이슈는 다른 에픽으로 옮길 수 있다 (하위 작업은 따라간다).

### 필드
- 제목: 1~255자, 앞뒤 공백 제거.
- 설명: 마크다운.
- 담당자: 프로젝트 멤버 중 1명 또는 미배정.
- 기한: 날짜만. 지난 날짜도 넣을 수 있고, 기한이 지난 미완료 이슈는 빨간색으로 표시한다.

### 완료
- `DONE` 분류 상태로 들어가면 `resolved_at`에 그 시각을 넣고, 다른 분류로 나가면 비운다.
- 완료 여부·진행률은 상태 이름이 아니라 **분류**로 판단한다.
- 에픽 진행률 = 하위 이슈 중 `DONE` 분류 이슈 수 ÷ 하위 이슈 수. 하위 작업은 세지 않는다.

### 삭제
- 관리자 또는 보고자만, 확인 창을 거쳐 지운다. **복구할 수 없다.**
- 함께 지워지는 것: 그 이슈의 **하위 작업**, 댓글, 레이블 연결, 관련 알림.
- 에픽을 지우면 아래 이슈는 남고 부모만 비워진다.
- 확인 창에 함께 지워지는 하위 작업 수를 보여준다.
- 이슈를 끝낼 때는 삭제가 아니라 완료 상태로 옮기도록 안내한다.

## 백로그 · 스프린트

### 스프린트 사용 옵션

프로젝트마다 스프린트를 쓸지 고른다 (`projects.sprint_enabled`).

| | 켬 (스크럼, 기본) | 끔 (칸반) |
|---|---|---|
| 백로그 · 스프린트 화면 | 있음 | 없음 (메뉴에서 숨김) |
| 보드에 나오는 이슈 | 진행 중 스프린트의 이슈 | 모든 이슈 |
| 새 이슈 | 백로그에서 만들면 백로그, 보드에서 만들면 진행 중 스프린트 | 보드의 첫 번째 열 |

- 관리자만 바꿀 수 있다.
- **끄기**: 진행 중 스프린트가 있으면 끌 수 없다. 먼저 완료한다. 계획된 스프린트와 이슈의 `sprint_id`는 그대로 두고 화면에서만 숨긴다. 다시 켜면 그대로 보인다.
- **켜기**: 언제든 켤 수 있다. 모든 이슈가 백로그에서 시작한다.
- 끈 상태의 보드에서 완료(`DONE` 분류) 열에는 **최근 14일 안에 완료된 이슈**만 보여준다. 오래된 완료 이슈가 쌓여 보드가 길어지지 않게 한다.

> 아래 규칙은 스프린트 사용이 켜진 프로젝트에 적용된다.

### 스프린트 상태

```
계획(FUTURE) ──시작──▶ 진행 중(ACTIVE) ──완료──▶ 종료(CLOSED)
```

- **진행 중 스프린트는 프로젝트당 1개.** 진행 중 스프린트가 있으면 다른 스프린트를 시작할 수 없다.
- 계획된 스프린트는 여러 개 만들 수 있다.
- **상태는 날짜로 바뀌지 않는다.** 관리자가 시작·완료 버튼을 누를 때만 바뀐다. 시작일이 되어도 자동으로 시작하지 않는다.
- 되돌리기 없음: 종료된 스프린트를 다시 열 수 없다.

### 생성 · 시작
- 이름 기본값은 `{프로젝트 키} 스프린트 {n}` (n은 그 프로젝트의 스프린트 수 + 1). 1~100자.
- 시작할 때 시작일(기본 오늘), 종료일(기본 시작일 + 14일), 목표를 정한다. 종료일은 시작일 이후여야 한다.
- 이슈가 없는 스프린트도 시작할 수 있다.
- 종료일이 지나도 자동으로 완료되지 않는다. 보드에 "종료일 지남"을 표시하고 관리자가 직접 완료한다.

### 이슈 넣고 빼기
- 이슈는 **스프린트 하나에만** 속한다. 스프린트가 없으면 백로그에 있다.
- **에픽은 스프린트에 넣지 않는다.** 에픽은 여러 스프린트에 걸치기 때문이다.
- **하위 작업은 부모의 스프린트를 따라간다.** 하위 작업만 따로 옮길 수 없고, 부모를 옮기면 함께 옮겨진다.
- 종료된 스프린트에는 넣거나 뺄 수 없다.
- 진행 중 스프린트에 이슈를 넣거나 빼도 된다 (범위 변경). 보드에 바로 반영된다.

### 완료
- 진행 중 스프린트를 완료하면 이슈를 나눈다.
  - `DONE` 분류 이슈: 그 스프린트에 남는다 (지난 스프린트 기록).
  - 나머지 이슈: 백로그 또는 계획된 스프린트 중 고른 곳으로 옮긴다.
- 완료하면 `state = CLOSED`, `completed_at`을 기록한다.

### 삭제
- **계획된 스프린트만** 지울 수 있다. 진행 중이면 먼저 완료하고, 종료된 스프린트는 기록이라 지우지 않는다.
- 지우면 그 스프린트의 이슈는 백로그로 돌아간다.

### 백로그 화면
- 순서: 진행 중 스프린트 → 계획된 스프린트(만든 순) → 백로그.
- 백로그에는 스프린트 없는 이슈 중 **에픽과 하위 작업을 뺀** 이슈가 나온다. 하위 작업은 부모 이슈 안에 접어 보여준다.
- 완료(`DONE` 분류)된 이슈는 백로그에서 숨긴다. 이슈 목록(검색)에서는 볼 수 있다.

### 보드
- 보드에는 **진행 중 스프린트의 이슈**만 나온다. 에픽은 나오지 않는다 (스프린트 사용을 끈 프로젝트도 마찬가지).
- 진행 중 스프린트가 없으면 빈 보드와 함께 백로그로 가는 안내를 보여준다.

## 순서 (rank)

보드의 같은 열 안, 백로그·스프린트 목록 안의 순서는 `issue_rank`(문자열) 오름차순이다. 보드와 백로그가 같은 값을 쓰므로 한쪽에서 바꾼 순서가 다른 쪽에도 반영된다.

- 새 이슈는 들어가는 목록(백로그, 스프린트, 보드 열)의 **맨 아래**에 들어간다.
- 드래그로 옮기면 놓은 자리의 **앞뒤 이슈 rank의 중간값**을 새 rank로 쓴다. 다른 이슈의 rank는 바꾸지 않는다.
- 상세 화면에서 상태를 바꾸면 새 열의 맨 아래로 간다.

### 중간값 만드는 규칙
- rank는 문자열 앞에 `0.`을 붙인 소수로 보고, 두 값의 중간 소수를 문자열로 만든다. 예: `"1"`과 `"2"` 사이 → `"15"`
- 맨 앞에 넣을 때는 `""`(0)과 첫 값 사이, 맨 뒤에 넣을 때는 마지막 값과 `1` 사이의 중간을 쓴다.
- **끝자리가 가장 작은 글자(`0`)인 값을 만들지 않는다.** `"1"`과 `"10"` 사이에는 값을 넣을 수 없기 때문이다.
- 자릿수 제한이 없으므로 재정렬 작업은 하지 않는다.

## 대시보드

- **프로젝트 단위**다. 프로젝트 멤버 모두 같은 위젯을 본다 (관리자·멤버 구분 없음).
- 위젯 구성·순서는 고정이다. 사용자가 추가·삭제·배치할 수 없다.
- "미완료" = 상태 분류가 `DONE`이 아닌 것. "해결" = `resolved_at`이 기록된 것.
- **에픽은 이슈 수 집계에서 뺀다** (DASH-2~5). 에픽은 하위 이슈의 묶음이라 함께 세면 중복된다. 하위 작업은 센다.
- 생성 · 해결 추이(DASH-6)는 날짜를 **사용자 기기 시간대** 기준으로 나눈다. DB에는 UTC로 저장되어 있으므로 변환해서 센다.
- 스프린트 진행률(DASH-7)은 진행 중 스프린트의 이슈 중 `DONE` 분류 비율이다. 하위 작업은 세지 않는다 (에픽 진행률과 같은 기준). 진행 중 스프린트가 없거나 스프린트 사용이 꺼져 있으면 위젯을 숨긴다.
- 데이터는 화면을 열 때 계산한다. 따로 집계 테이블을 두지 않는다.

## 레이블

- 이름은 1~50자, 공백 없이. 같은 프로젝트에서 겹칠 수 없다 (대소문자 구분 없이 비교).
- 이슈에 붙일 때 없는 이름이면 새로 만든다.
- 이슈 하나에 같은 레이블은 한 번만 붙는다.
- 어느 이슈에도 붙지 않은 레이블은 자동완성 목록에서 숨긴다 (지우지는 않는다).

## 댓글

- 내용 1자 이상, 마크다운.
- 멘션은 프로젝트 멤버만 할 수 있다. 저장은 `@{userId}`, 화면에는 `@이름`으로 보여준다.
- 수정하면 "수정됨"을 표시한다.
- 삭제하면 바로 사라진다. **복구할 수 없다.**

## 알림

### 알림이 생기는 경우

| 종류 | 언제 | 받는 사람 |
|---|---|---|
| `ASSIGNED` | 담당자가 지정·변경됐을 때 | 새 담당자 |
| `MENTIONED` | 댓글에서 멘션됐을 때 | 멘션된 사람 |
| `COMMENTED` | 댓글이 달렸을 때 | 보고자, 담당자 |
| `STATUS_CHANGED` | 상태가 바뀌었을 때 | 보고자, 담당자 |

- **자기가 한 행동은 자기에게 알리지 않는다.**
- 한 번의 행동으로 같은 사람이 여러 종류에 해당하면 **하나만** 보낸다. 우선순위: `MENTIONED` > `ASSIGNED` > `COMMENTED`·`STATUS_CHANGED`.
- 프로젝트 멤버가 아닌 사람에게는 보내지 않는다.

### 읽음
- 알림을 누르면 그 이슈로 이동하고 읽음 처리한다. "모두 읽음"으로 한 번에 처리할 수 있다.
- 이슈가 지워지면 그 이슈의 알림도 지워진다.

## 사용자

### 가입
- 이메일: 형식 검사, 서비스 전체에서 겹칠 수 없다 (대소문자 구분 없이 비교).
- 비밀번호: 8~64자, 영문과 숫자를 모두 포함. BCrypt 해시로 저장한다.
- 이름: 1~50자.

### 로그인 (JWT)
- 로그인하면 액세스 토큰(30분)과 리프레시 토큰(14일)을 받는다. 자세한 흐름은 [API 명세: 인증](../spec/api-spec.md#인증-jwt).
- 액세스 토큰이 만료되면 화면이 자동으로 재발급받는다. 리프레시 토큰까지 만료되면 로그인 화면으로 간다 (14일 동안 안 쓰면 다시 로그인).
- 리프레시 토큰은 한 번 쓰면 바뀐다. 이미 쓴 토큰으로 재발급을 시도하면 거절한다.
- 기기마다 따로 로그인을 유지한다. 로그아웃은 그 기기만 로그아웃한다.
- **비밀번호를 바꾸면 다른 모든 기기에서 로그아웃**된다 (지금 기기는 새 토큰을 받아 유지).
- 웹은 리프레시 토큰을 HttpOnly 쿠키에 둔다 (스크립트로 읽을 수 없게). 앱은 기기의 암호화 저장소에 둔다.

### 탈퇴
- 계정을 **즉시 지운다. 복구할 수 없다.** 같은 이메일로 다시 가입할 수 있다.
- **리드인 프로젝트가 있으면 탈퇴할 수 없다.** 리드를 넘기거나 프로젝트를 지운 뒤 탈퇴한다.
- 마지막 관리자인 프로젝트가 있어도 탈퇴할 수 없다.
- 탈퇴하면
  - 멤버십과 받은·보낸 알림이 지워진다.
  - 담당자였던 이슈는 미배정이 된다.
  - 만든 이슈·쓴 댓글은 남고, 작성자는 **"알 수 없는 사용자"** 로 보인다.

## 정하지 않은 것

| 항목 | 메모 |
|---|---|
| 비밀번호 찾기 | 이메일 발송이 필요해 MVP 제외 여부 결정 |
| 알림 보관 기간 | 오래된 알림 자동 삭제 여부 |
