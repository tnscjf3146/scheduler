## 정한 것

### 색 (Figma 변수)

전체적으로 흑백이고, 색은 필요한 곳에만 칠한다. 완전한 흰색 · 검정은 쓰지 않는다.

| 컬렉션 | 내용 |
|---|---|
| Primitives (25) | 인디고 50 · 100 · 500 · 600 · 700 / 그레이 0 · 50 ~ 900 (`gray/0` `#FDFDFD`, `gray/900` `#222227`) / 포인트 보라 · 초록 · 파랑 · 빨강 · 청록 / 상태 분류용 슬레이트 100 · 500, 에메랄드 50 · 600 |
| Color (Light, 38) | 쓰임새별 이름. 모두 Primitives를 가리킨다 |
| Spacing | 4 · 8 · 12 · 16 · 20 · 24 · 32 · 48 |
| Radius | 0 · 4 · 6 · 8 · 12 · 999 |

- **메인 컬러**: 인디고 `#4F46E5` (`color/action/primary`). 주요 버튼 · 포커스 · 선택 아이콘에만 쓴다.
- **배경(`color/bg/*`)**: 전부 그레이. 선택 · 마우스 올림도 회색(`bg/selected`, `bg/hover`)으로 표시한다. 어두운 면(툴팁 · 머리글)은 `gray/900`.
- **글자(`color/text/*`)**: 검정 · 흰색이 기본, 파랑(`text/accent`, 링크) · 빨강(`text/danger`, 오류 · 기한 지남 · 삭제)만 색. 보조 글자는 검정 계열 회색.
- **이슈 유형 색**: 에픽 보라 · 스토리 초록 · 작업 파랑 · 버그 빨강 · 하위 작업 청록.
- **상태 분류 색 (2026-11-06 결정)**: `color/status/*`. 할 일 슬레이트 `#64748B` · 진행 중 인디고 `#4338CA` · 완료 에메랄드 `#059669`, 각각 옅은 바탕색(`*-subtle`)도 있다.
- 다크 모드는 만들지 않았다.

### 글자

- **Pretendard로 한다.** 다만 지금 Figma 환경에 Pretendard가 설치돼 있지 않아 Noto Sans KR로 들어가 있다 (아래 남은 일).
- 텍스트 스타일 8개: Display 32 · Heading/H1 24 · H2 18 · H3 15 · Body/L 14 · Body/M 13 · Caption 12 · Label 11.

### 아이콘

- 출처는 **Lucide** (24px, 선 2px, 둥근 끝). 없는 것만 같은 규격으로 직접 그린다. 라이선스는 [에셋 목록](asset/asset-list.md)과 시안 파일 주석에 적었다.
- 컴포넌트 이름: `icon/{묶음}/{이름}` (예: `icon/top/bell`, `icon/type/bug`). 색은 Color 변수에 연결돼 있다.
- **이슈 유형: 상자 세트** — 에픽 `boxes` · 스토리 `package` · 작업 `box` · 버그 `package-x` · 하위 작업 `puzzle`.
- **우선순위: 등급 글자** — 가장 높음 S · 높음 A (빨강) · 보통 B · 낮음 C · 가장 낮음 D (회색).
- **상태 분류**: 할 일 빈 원(`circle`) · 진행 중 재생 원(`circle-play`) · 완료 체크 원(`circle-check`). 진행 중 · 완료는 채운 원 안에 흰 기호.
- 시안 페이지에 남겨 둔 다른 후보: 이슈 유형 8세트, 우선순위 6안.

### 상태 분류 표시 (2026-11-06 결정)

| 쓰는 곳 | 표시 |
|---|---|
| 상태 배지 | 분류 색 글자 + 모양 아이콘, 배경 없음 |
| 보드 | 같은 분류 열들 위에 분류 띠 |
| 프로젝트 설정 · 상태 | 분류별 그룹, 그룹 머리에 분류 색 |
| 정책 | 보드 열은 할 일 → 진행 중 → 완료 순서로 묶이고, 순서는 같은 분류 안에서만 바꾼다 ([정책](policy/policy.md)) |

### 화면 규칙 (와이어프레임에서 정함, 기획 문서에는 아직 없음)

| 항목 | 정한 내용 |
|---|---|
| 사이드바 | 접기 · 펼치기 토글. 프로젝트 안은 `Type=Project`, 프로젝트 밖(목록 · 진행 현황 · 체크리스트)은 `Type=Home` |
| 진행 현황 (03) | 프로젝트당 한 줄. 스프린트 이름 · 기간 · D-day, 진행률, 이슈 수, 기한 지남. 이슈 목록은 펼치기(▲/▼), 5개만 보이고 "더보기" |
| 체크리스트 (04) | 내가 담당인 이슈만. 위젯은 진행 현황과 같은 모양, 진행률은 내 이슈 기준. 위에 "백로그에 생성" · "스프린트에 생성" 버튼 |
| 진행률 | 스크럼 + 진행 중 스프린트 있음 → 스프린트 기준 % / 스크럼 + 없음 → "진행 중인 스프린트가 없어요" / 칸반 → 전체 이슈 기준 % |
| 이슈 생성 버튼 | 칸반은 "+ 이슈 생성" 하나 (백로그 · 스프린트가 없다). 진행 중 스프린트가 없으면 "스프린트에 생성"은 비활성 + 툴팁 |
| 스프린트 (07) | 사이드바에서 보드 위. 진행 중 · 계획됨 · 완료로 나눠 보여 주고, 만들기 · 삭제(계획된 것만) 가능 |
| 상단 버튼 | "만들기" → "이슈 만들기" |
| 삭제 비활성 | 분류(상태) · 계층(이슈 유형)의 마지막 하나는 삭제 비활성 + 툴팁 |
| 알림 | 벨 아래 드롭다운(560px), 창 안에서 스크롤. 알림 없음 화면 따로 |

## 다른 컴퓨터에서 이어서 하기

1. 저장소를 받고 `develop` 브랜치로 간다: `git clone https://github.com/tnscjf3146/scheduler.git && git switch develop`
2. Claude Code에 같은 계정의 Figma 연결이 돼 있는지 확인한다 (Figma 파일은 클라우드에 있어서 그대로 이어진다).
3. Claude Code에 이 문서를 먼저 읽게 한다. 예: "`docs/design/design-progress.md` 읽고 남은 일 이어서 하자".
4. 아이콘 시안을 다시 고치려면 `draft/issue-icon-options.html`을 직접 고치면 된다. 아이콘 SVG가 파일 안에 들어 있어서 외부 파일이 필요 없다.
5. 작업이 끝나면 이 문서의 "정한 것"과 "남은 일"을 갱신한다.
