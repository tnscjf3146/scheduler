에이전트에게 무엇을, 어디로 알려 줄까

에이전트가 알아야 하는 내용은 세 층입니다. 각 시안은 이 세 층을 어디에 둘지가 다릅니다.

① 정체성 — 이름·역할·성격·작업 폴더 ② 서비스·MCP 사용법 — 앱 소개, 도구 목록, 결재·할 일 규칙 (고정) ③ 사용자 추가 — 사용자가 만든 스킬·하네스

한눈에 비교

#시안② 고정·자동 갱신작업 폴더에 파일Codex도 같게사용자가 고치기구현
1AGENTS.md 한 번 쓰기 (예전 방식)✕ 처음 한 번생김○파일 직접이미 있었음
2AGENTS.md 앱 관리 구역○ 매 시작생김○구역 밖은 자유작음
3정체성 하네스 + 기본 스킬 (지금)○ 매 시작없음✕ 따로 AGENTS.md앱 화면이미 있음
4시스템 프롬프트 파일 덧붙이기○ 매 시작없음✕ 확인 필요앱 화면 필요작음
5MCP 서버 instructions○ 앱과 함께없음△ 확인 필요✕ 앱이 고정작음
6도구 설명에 전부○ 앱과 함께없음○✕작음
7안내서 도구 (get_guide)○ 앱과 함께없음○✕작음
8CLAUDE.md 한 줄 + 앱 폴더 파일○ 매 시작한 줄만✕ Codex는 import 없음앱 폴더 파일작음
9MCP instructions + AGENTS.md 정체성○ 앱과 함께생김(정체성만)△ 확인 필요정체성은 파일중간
10AGENTS.md 관리 구역 + 스킬 분리○ 매 시작생김○ (스킬 제외)구역 밖 + 스킬중간

노란 줄은 추천 후보입니다. "확인 필요"는 아직 Codex에서 직접 시험하지 않은 항목입니다.

시안 01

AGENTS.md를 처음 한 번 쓰기

에이전트를 만들 때 작업 폴더에 AGENTS.md를 쓰고, 그다음은 사용자 파일로 둡니다. 이 작업 전의 방식입니다.

① 정체성작업 폴더/AGENTS.md
② 서비스·MCP작업 폴더/AGENTS.md
③ 사용자 추가플러그인 (--plugin-dir)
장점
  • 가장 단순합니다
  • Claude Code·Codex가 같은 파일을 읽습니다
  • 사용자가 파일을 바로 고칩니다
단점
  • 앱이 새 도구를 추가해도 기존 에이전트는 모릅니다
  • 예전 에이전트는 파일이 없거나 낡습니다(dd 문제)
  • 사용자 프로젝트 폴더에 파일이 생깁니다

맞는 경우: 앱 기능이 더는 바뀌지 않을 때

추천 후보 시안 02

AGENTS.md에 앱 관리 구역 두기

AGENTS.md 안에 표시 줄로 감싼 "앱 구역"을 두고, 시작할 때마다 그 구역만 최신 내용으로 다시 씁니다. 구역 밖은 사용자 몫입니다.

① 정체성AGENTS.md 앱 구역
② 서비스·MCPAGENTS.md 앱 구역
③ 사용자 추가구역 밖 글 + 플러그인
장점
  • ②가 항상 앱 버전과 맞습니다
  • Claude Code·Codex 모두 같은 내용
  • 파일을 열면 무엇을 받는지 그대로 보입니다
  • 사용자 프로젝트의 기존 AGENTS.md 내용을 지키며 공존합니다
단점
  • 작업 폴더에 AGENTS.md·CLAUDE.md가 생깁니다
  • git 저장소면 변경 사항으로 잡힙니다
  • 사용자가 앱 구역을 고치면 다음 시작 때 사라집니다

맞는 경우: "AGENTS.md에 고정"이라는 생각을 그대로 따를 때

지금 코드 시안 03

정체성 하네스 + 기본 스킬

세션 시작 하네스가 정체성 글을 출력하고, 결재·할 일·도구 규칙은 기본 스킬 4개로 둡니다. 커밋 f2091cf의 방식입니다.

① 정체성SessionStart 하네스
② 서비스·MCP기본 스킬 4개
③ 사용자 추가같은 플러그인
장점
  • 작업 폴더를 건드리지 않습니다
  • 규칙을 앱 화면에서 고칩니다
  • 실제 실행으로 동작을 확인했습니다
단점
  • ②가 "고정"이 아니라 사용자가 고치거나 지울 수 있습니다
  • 스킬은 Claude가 필요할 때만 읽어서 놓칠 수 있습니다
  • Codex는 따로 AGENTS.md를 만들어야 합니다
  • 구조가 복잡해 설명하기 어렵습니다

맞는 경우: 규칙까지 사용자가 바꾸게 하고 싶을 때

시안 04

시스템 프롬프트 파일 덧붙이기

앱 폴더에 지시문 파일을 만들고 claude --append-system-prompt-file로 넘깁니다.

① 정체성앱 폴더/system.md
② 서비스·MCP앱 폴더/system.md
③ 사용자 추가플러그인
장점
  • 작업 폴더를 건드리지 않습니다
  • 항상 대화 맨 앞에 들어가 놓치지 않습니다
  • 매 시작마다 최신으로 만듭니다
단점
  • Codex에 같은 옵션이 있는지 확인이 필요합니다
  • 사용자가 내용을 보려면 앱 화면이 따로 필요합니다
  • Claude Code 옵션 이름이 바뀌면 깨질 수 있습니다

맞는 경우: Claude Code 에이전트만 쓸 때

추천 후보 시안 05

MCP 서버 instructions에 고정

MCP 연결 때 서버가 돌려주는 instructions에 서비스 소개와 도구 사용법을 넣습니다. Claude Code는 이 글을 대화에 넣어 줍니다.

① 정체성instructions (에이전트별 주소)
② 서비스·MCPinstructions
③ 사용자 추가플러그인
장점
  • "MCP 사용법은 MCP가 알려 준다" — 위치가 가장 자연스럽습니다
  • 앱을 고치면 즉시 모든 에이전트에 반영됩니다
  • 작업 폴더를 건드리지 않습니다
  • 사용자가 실수로 지울 수 없습니다
단점
  • Codex가 instructions를 읽는지 확인이 필요합니다
  • 사용자가 내용을 직접 볼 곳이 없습니다(앱 화면이나 문서 필요)
  • 너무 길면 다른 MCP 서버 안내와 섞여 묻힐 수 있습니다

맞는 경우: ②를 진짜 "고정"으로 두고 싶을 때

시안 06

도구 설명에 규칙을 모두 넣기

별도 안내 없이, 각 MCP 도구의 설명에 그 도구의 규칙을 자세히 씁니다. 예: submit_approval 설명에 결재가 필요한 일 목록.

① 정체성(없음 — 따로 필요)
② 서비스·MCP도구마다 description
③ 사용자 추가플러그인
장점
  • MCP를 지원하는 모든 CLI가 읽습니다
  • 도구를 쓸 때 바로 옆에 규칙이 있습니다
  • 추가 파일이 없습니다
단점
  • 정체성을 넣을 자리가 없습니다
  • "언제 결재를 올릴지" 같은 먼저 알아차릴 판단은 도구를 보기 전엔 모릅니다
  • 도구 설명이 길어져 매번 토큰을 씁니다

맞는 경우: 다른 방식의 보조로

시안 07

안내서 도구 (get_guide)

MCP에 get_guide 도구를 두고, 처음에 그것을 부르라고만 알려 줍니다. 안내서는 앱이 돌려줍니다.

① 정체성get_guide 결과
② 서비스·MCPget_guide 결과
③ 사용자 추가플러그인
장점
  • 어떤 MCP CLI에서도 동작합니다
  • 앱과 함께 항상 최신입니다
  • 작업 폴더를 건드리지 않습니다
단점
  • AI가 부르지 않으면 아무것도 모릅니다
  • "처음에 부르라"는 말을 다른 곳(시안 5나 6)에 또 써야 합니다
  • 호출 한 번만큼 느려집니다

맞는 경우: 긴 상세 설명을 필요할 때만 주고 싶을 때

시안 08

CLAUDE.md 한 줄 + 앱 폴더 파일

작업 폴더 CLAUDE.md에는 @C:\...\Scheduler\agents\<id>\scheduler.md 한 줄만 두고, 내용은 앱 폴더 파일을 매 시작마다 새로 씁니다.

① 정체성앱 폴더/scheduler.md
② 서비스·MCP앱 폴더/scheduler.md
③ 사용자 추가CLAUDE.md 나머지 + 플러그인
장점
  • 작업 폴더에는 한 줄만 생깁니다
  • 항상 최신입니다
  • Claude Code의 기본 기능(@import)만 씁니다
단점
  • Codex의 AGENTS.md는 import를 지원하지 않습니다
  • 절대 경로라 폴더를 옮기면 깨집니다
  • 한 줄이라도 git 변경으로 잡힙니다

맞는 경우: Claude Code 위주이고 폴더를 최대한 깨끗하게 두고 싶을 때

추천 후보 시안 09

MCP instructions + AGENTS.md 정체성

바뀌면 안 되는 ②는 MCP instructions에 고정하고, 사람이 고치는 ①은 AGENTS.md에 둡니다. ③은 스킬·하네스입니다.

① 정체성작업 폴더/AGENTS.md
② 서비스·MCPMCP instructions
③ 사용자 추가플러그인
장점
  • 고정할 것과 고칠 것이 자리로 나뉩니다
  • 앱이 업데이트되면 ②는 자동 반영
  • 정체성은 파일을 열어 바로 고칩니다
단점
  • 세 곳으로 나뉘어 처음 보면 헷갈립니다
  • 작업 폴더에 AGENTS.md는 여전히 생깁니다
  • Codex의 instructions 지원 확인이 필요합니다

맞는 경우: 장기적으로 가장 관리하기 쉬운 구조를 원할 때

시안 10

AGENTS.md 관리 구역 + 규칙은 스킬

AGENTS.md 앱 구역에는 정체성, 서비스 소개, 도구 목록만 짧게 두고, 자세한 규칙(결재 기준, 날짜 규칙)은 기본 스킬로 둡니다.

① 정체성AGENTS.md 앱 구역
② 서비스·MCP앱 구역(요약) + 기본 스킬(상세)
③ 사용자 추가플러그인
장점
  • AGENTS.md가 짧아 매번 쓰는 토큰이 적습니다
  • 상세 규칙은 화면에서 고칠 수 있습니다
  • 도구 목록은 항상 보입니다
단점
  • Codex는 스킬을 못 읽어 상세 규칙을 모릅니다
  • 규칙이 두 곳에 나뉘어 관리 부담이 있습니다
  • 스킬을 놓칠 위험이 남습니다

맞는 경우: 규칙이 길어지고 Claude Code가 주력일 때

추천

바로 쓰기에는 시안 02가 맞습니다. 말씀하신 "AGENTS.md로 서비스와 MCP 사용법을 고정"을 그대로 따르면서, 앱이 바뀌어도 매 시작마다 최신으로 맞춰지고, Claude Code와 Codex가 같은 내용을 봅니다.

길게 보면 시안 09가 더 깔끔합니다. MCP 사용법을 MCP 서버가 직접 알려 주므로 파일이 낡을 일이 없습니다. 다만 Codex가 MCP instructions를 읽는지 먼저 시험해야 합니다.

어느 쪽이든 사용자 스킬·하네스(③)는 지금처럼 플러그인으로 둡니다.

시안 05·09의 "Claude Code는 MCP instructions를 대화에 넣는다"는 Claude Code에서 확인된 동작입니다. Codex 쪽 지원 여부, 시안 04의 Codex 옵션은 아직 확인하지 않았습니다.
